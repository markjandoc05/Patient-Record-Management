## 1. Migration/schema

Add `003_services.sql`: service_categories, services and service_branch_settings
only. UUID keys, global normalized unique names including inactive entries,
nullable numeric(12,2) prices, duration checks, version and actor/timestamp fields.
Existing numbered/checksummed runner; additive migration, no catalogue seed.
Forward migration `004_services_name_identity.sql` corrects whitespace/case name identity and whitespace-only constraints without modifying checksummed migration 003 or stored display names. See [schema details](../services-schema.md).

## 2. Branch FK

The proposed FK worked exactly as designed. Actual development app_records has
a text composite primary key(collection_path,id). Settings fix collection_path
to branches and reference that pair with DELETE RESTRICT. FK/unique/check failures
were exercised on synthetic PostgreSQL 17. Branch deletion now reports that service
settings reference it and directs users to deactivate instead.

## 3. Backend/API

Dedicated backend/services.ts mounts all seven specified GET/POST/PATCH routes.
List supports search, category, status, authorized branch and availability filters,
and pagination (default 25, maximum 100 per page). Details expose canonical values
and only authorized branch configuration. Unknown/server-owned input fields and
invalid identifiers/types are rejected. No hard-delete endpoint.

## 4. Permissions

Administrator and existing allowed Support role variants can write. The uppercase
SUPPORT_DEVELOPER role still requires the existing isolated development guard.
Manager, doctor and staff read only; active profile rechecked transactionally.
Anonymous, inactive and pending users denied. Standard authenticated session,
origin/CSRF handling and protected-cache invalidation reused. Normal users receive
only assigned branch settings; other-branch direct/list probes are denied.

## 5. Prices and availability

Standard priced/free/unpriced and branch inherit/priced/free express request intent.
Money arrives as positive decimal strings, explicit zero through Free, null through
unpriced/inherit. Reject >2 decimal places rather than rounding. Price inheritance
is override ?? standard, so a zero override remains Free. Operational availability
requires active service + active branch + stored available=true. Missing rows stay
unavailable. New inactive-branch enabling rejected; existing enabled settings can
be retained but remain operationally unavailable. No branch duration override.

## 6. Concurrency/retries

Service/category PATCH requires expectedVersion. Canonical or branch changes advance
one parent service version; stale requests return 409 and never merge. No-op updates
preserve version. UI locks stale fields/save and offers Reload and review. Stable
create UUID survives retries; equivalent normalized same-actor payload returns the
existing record without duplicate audit. Different content returns 409. After a lost
PATCH response, retrying its stale version returns 409; GET resolves the committed
result. Two real browser editors confirmed the newer description survives.

## 7. Audit and atomicity

Reuse JSONB audit_logs, no new audit table. Trusted server actor, timestamp, event
type and before/after values accompany creates/edits/status/prices/branch changes
and category lifecycle changes. Service, branch settings and audit commit together.
Invalid branch/category, stale version and injected audit failure all leave no
partial configuration. Services explicitly records all authorized actors including
Support; the committed foundation audit policy is unchanged. Audit viewer
adds Services/category filters, before→after values and explicit money-state labels.

## 8. UI

## 17. Correctness repair review

1. Category UUIDs previously retained request casing while PostgreSQL returned a
   canonical UUID. Validated UUIDs now use canonical lowercase representation for
   service/category IDs and category associations before storage/comparison. The
   existing UUID grammar is unchanged. Uppercase and lowercase retries return the
   same service; different category identity still conflicts.
2. Branch settings previously compared ordered arrays, mixing SQL order and
   localeCompare. Comparison now keys by exact case-sensitive branch ID, checks
   collection cardinality and compares availability/override values. Array order
   cannot alter identity. Different values, case-distinct IDs, missing/extra rows
   remain conflicts. Replay/concurrent retry creates no duplicate rows or audit.

   tabs as spaces. New migration 004 normalizes all JavaScript name whitespace,
   collapses runs before trimming, then lowercases. Both tables share one immutable
   SQL function, unique indexes and nonblank checks. Locks/preflight detect existing
   collisions or blank names and abort transactionally; no automatic merges,
   deletions or display-name updates. Existing length constraints remain intact.

## 20. P2 Services mutation-generation repair

The final review found that service/category POST/PATCH saves supplied no abort
signal or scope predicate to servicesRequest. A held Administrator save denial,
delivered after the keyed workspace changed to Staff assigned only A, invoked
foundation invalidation before the UI catch handler. Keyed editor reset protected
new UI state but did not protect the shared current-scope subscriptions. This was
a client response-lifetime gap, not a backend authorization bypass.

Exact path: ServiceEditor.save or CategoryManager.save → servicesRequest awaits
and decodes the API response → current 401/403 handling invokes existing
invalidateProtectedData → rejected request reaches the component catch. Services
API is the sole Services denial-invalidation owner; components do not invalidate,
and the generic foundation remains unchanged. The corrected adapter now checks
abort and the captured current-generation predicate before fetch and after decode,
before that existing denial path. Current 401/403 still invalidates exactly once.

Both editors reuse the dashboard authorization context/generation. A shared local
mutation hook captures that generation and its component lifetime/request identity,
aborts replaced requests and aborts in layout cleanup on close/unmount/scope change.
Success, catch and finally callbacks act only while the request is current.
Service create/edit/status/branch price/availability all share the service save;
category create/rename/status all share category save. No second authorization
identity model, new role policy or foundation cache behavior was introduced.

Old success does not close/reset a current editor, overwrite drafts, refresh a new
scope or render old confirmation. Old denial/conflict cannot clear current cache
or display a stale error; A→B→A still differs by generation. Current 409 retains
save locking and Reload/review. Busy service Back/Cancel and category Cancel edit
remain disabled; closing category management or leaving its workspace aborts the
pending child request. Retry remains an explicit user action and reuses create UUID.

Abort/discard does not prove the backend write failed or undo a committed write.
No blind automatic retry was added. The new scope loads its authorized catalogue;
existing detail GET/version checks reconcile saves when the user returns/reviews.
Version conflicts and atomic writes remain authoritative at the backend.

The same current-generation predicate also reaches list/category/detail adapter
calls. Review found the equivalent read-denial interval between new layout scope
